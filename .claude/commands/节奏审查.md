# /节奏审查

你是章节节奏审查 Agent。执行本命令时，由当前 Claude Code 实例直接阅读章节并做语义判断，不调用外部 API。

## 参数

从用户输入 `$ARGUMENTS` 中识别：
- `--project-root <项目目录>`：小说项目根目录。缺失时询问用户。
- `--chapter-file <章节文件>`：当前章节正文。可为绝对路径或相对 project-root。缺失时优先选择 `03_manuscript/` 中最新章节，无法判断时询问用户。

## 执行步骤

1. 读取当前章节正文。
2. 读取 `00_memory/novel_plan.md`、`00_memory/novel_state.md`（存在才读）。
3. 判断本章节奏档位：慢档 / 中档 / 快档。
4. 核查 A/B/C 配额：
   - A：主线矛盾实质推进。
   - B：主要关系决定性升级。
   - C：核心秘密完整揭露。
5. 检查章末悬念质量与隐性加速。
6. 写入门禁产物：
   - `04_editing/gate_artifacts/<chapter_id>/pacing_review.md`

## pacing_review.md 固定格式

必须严格使用以下模板，便于脚本解析：

```markdown
# 节奏审查报告

## 一、档位判断
- **本章档位**：[慢档 / 中档 / 快档]
- **判断依据**：[1-2句：主要场景类型、核心矛盾推进幅度]

## 二、A/B/C 配额核查
- **A（主线矛盾实质推进）**：[触发 / 未触发] — [简要说明]
- **B（主要关系决定性升级）**：[触发 / 未触发] — [简要说明]
- **C（核心秘密完整揭露）**：[触发 / 未触发] — [简要说明]
- **配额违规**：[是 / 否]（同时触发 ≥2项 = 违规）

## 三、章末悬念质量
- **悬念等级**：[强 / 中 / 弱 / 无]
- **具体悬念内容**：[用一句话描述章末留下的钩子]

## 四、隐性加速检测
- **是否存在关键词未覆盖的隐性加速**：[是 / 否]
- **说明**：[如有，描述具体表现；无则写"无"]

## 综合结论
节奏审查: [通过 / 失败]
失败原因: [若失败，填写具体原因；通过则填"无"]
```

## 失败标准

以下任一情况，综合结论必须为“失败”：
- A/B/C 同时触发 2 项及以上。
- 存在关键词未覆盖的隐性加速。
- 章末悬念等级为“无”且不是慢档收尾。

## 禁止事项

- 不得为通过门禁而弱化真实问题。
- 不得修改 `gate_result.json`。
- 不得把审查报告写入章节正文。
